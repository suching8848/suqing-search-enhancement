当前工坊ID、可见性与上传状态见[workshop-item.json](publishing/workshop-item.json)。release/中的冻结manifest保留准备时状态；其中历史uploaded=false不代表当前工坊状态。

[English](README.en.md)

0.1.2，面向 Project Zomboid B42.21 单人游戏。Mod ID 为 `SuQingSearchEnhancement`。本次修复拖拽物品结束后直接搜索仍不置顶的问题，保留现有沙盒、高亮和刷新适配。用户于 2026-11-07 确认当前本机单人配置中修复有效；其余验证范围见下文。

按 **F8** 打开搜索面板。选择随身或附近后，在原背包、搜刮的详细列表及容器图标上查看匹配标记和命中数。增强命中行显示紫色边框，并沿用 CleanUI 原搜索颜色显示黄色高亮；选中或悬停时保留原背景，紫边继续标记命中。堆叠行的 `2/5` 表示其中两件匹配。物品栏右键入口默认隐藏，可在模组设置中开启。匹配的物品组默认移到列表前面，两组内部沿用当前原排序。清空后恢复原排序，设置中可关闭置顶。拖拽、按住鼠标和框选期间延后重排，结束后恢复置顶；无需再次点击物品列表。

| 输入 | 效果 |
| --- | --- |
| `酿酒` | 名称包含酿酒 |
| `@舌尖 酿酒 -书` | 来源模组包含舌尖、名称包含酿酒、排除书 |
| `&Chinesecuisine.BrewingBook34` | 完整物品 ID 精确匹配，ASCII 字母忽略大小写 |
| `扳手 \| 锤子` | 匹配任一组，组内空格为同时满足 |
| `@"Mod Name" "item name"` | 引号将含空格的文字组合为一个条件，仍按宽松文字规则匹配 |
| `@原版` 或 `@vanilla` | 游戏标记的原版来源 |

名称、物品类型名及模组显示名支持不区分 ASCII 大小写的部分匹配，并宽松处理空白、连字符、下划线和拼音分音撇号。这不是拼写纠错；引号也不要求文字和空格完全相等。`@` 后的 Mod ID 使用忽略 ASCII 大小写的字面部分匹配；`&` 后的完整物品 ID 只做忽略 ASCII 大小写的严格相等比较，不使用拼音或分隔字符宽松匹配。

拼音复用已启用的可选模组 `yxjs_PinYinSearch`，已检查其 1.3 API，支持全拼、首字母及其提供的多音字候选。`NIUROUBING`／`NRB` 可搜牛肉饼，`M110BQ` 可搜 M110 步枪，`@SQ` 可搜来源名称包含蘇清的物品。简繁体与多音字覆盖取决于上游词典和候选读音，不保证所有汉字与读音。同音词会同时命中：`bianzhi` 可匹配“编织”和物品状态“变质”；只找编织类可输入 `编织` 或 `bianzhi -变质`。本模组不附带该词典；未启用或无法取得拼音接口时，字面名称及大小写宽松匹配仍可使用。

`@` 按真实来源 Mod ID 及游戏中的模组名称匹配。`Base` 脚本命名空间和 Workshop ID 不作为来源判据。所有组合条件须由同一件物品满足。输入未完成时显示用法提示并清理旧标记。

在 **设置 → 模组设置 → 蘇清的搜索增强** 调整以下八项设置。原生设置接口随游戏提供，核心无需外部前置。下列为首次使用时的默认值，已保存的个人设置优先。

| 设置 | 默认值 |
| --- | --- |
| 接入已适配的库存搜索框 | 开启 |
| 左键点击搜索框弹出面板 | 关闭 |
| 打开面板快捷键 | F8 |
| 显示容器命中数和堆叠匹配数 | 开启 |
| 首次打开时展开搜索用法 | 关闭 |
| 拼音匹配（需可用的上游接口） | 开启 |
| 将匹配结果置顶 | 开启 |
| 显示物品栏右键菜单入口 | 关闭 |

右键入口开关在下一次打开菜单时生效。文字输入期间不会触发面板快捷键。

另在 **沙盒设置 → 蘇清的搜索增强 → 原搜索框接管方式** 选择世界的接管模式。这是独立于上述八项个人模组设置的沙盒选项，默认 **全部接管**；已有存档缺少该值时也使用全部接管，不自动修改存档。改为 **仅特殊语法接管** 后，原框中的普通单词／中文名称保留原搜索方法和黄色高亮，只有 `@来源`、`&完整ID`、`-排除`、`|`、双引号或多个以空白分隔的 AND 条件才启动增强。两端空白、名称中间的普通连字符／`@`／`&` 不会单独触发。`扳手 锤子` 属于 AND 特殊语法；输入未完成的特殊语法仍由增强显示错误。独立 F8 面板始终主动使用增强搜索。新档在创建时配置；现有档需通过可用的沙盒设置界面调整，保存并正常重进后核对。

CleanUI 2.10.4 的库存搜索框默认接入。默认“全部接管”时，所有非空名称查询统一使用增强匹配，包括普通单词、全拼、首字母和组合表达式；“仅特殊语法接管”时按上述语法切换，普通输入不添加增强边框、计数或置顶。类别模式沿用原界面；组合名称＋类别时仍同时满足类别条件。开启左键弹出后，可直接带入文字、类别和范围。面板和已接入输入框同步文字。关闭接入后，独立面板仍由 F8 打开。其他 UI 可用通用快捷键及物品栏右键入口，其专有输入框需单独适配。

附近范围取当前搜刮 UI 已列出、可访问且已探索的真实容器及可见地面。随身范围取物品栏列出的主包及随身包。Proximity Inventory 和 CleanUI 汇总栏只投影可读真实来源，按实际物品实例去重。搜索读取现有物品，不扫描全地图、不递归扫描界面未列出的背包，也不自动打开、探索或生成容器内容。数据在输入及容器变化后合并刷新，活动查询另有一秒刷新兜底。

已读取的兼容目标包括原版 UI、CleanUI 2.10.4、拼音搜索 1.3、Proximity Inventory，以及相关拼音、选择和转移补丁。原有转移、选择和配方函数保留其调用链；置顶在原排序完成后稳定分组，并跟随 NeatUI 实际绘制的过滤列表、原地排序及绘制过程中产生的列表刷新；过滤和切换排序后继续重新分组。高亮和置顶适配详细列表视图，图标网格视图未适配。未知 UI 的自定义分隔行会保留分段边界，因此不承诺跨这些边界全局置顶。

此前 0.1.0／rc.3 收到过本机单人功能正常反馈；用户于 2026-11-07 再次确认当前 0.1.2 搜索置顶修复有效。该确认不代表逐项验收全部沙盒模式、完整英文界面、手柄、所有第三方组合、其他游戏版本、多人／服务器或性能收益，这些仍需分别验证。

## 安装与验收

本地安装时，将包内的 `mods/SuQingSearchEnhancement` 文件夹复制到 `%UserProfile%\Zomboid\mods\`，然后在目标存档的模组管理中启用 `SuQingSearchEnhancement`。已经启用本模组时，正常退出游戏后更新该文件夹，再重启游戏。不要将文件覆盖到其他模组目录。可选拼音模组需单独安装并启用。

可按以下步骤检查自己的游戏环境；它们不是已经全部完成的验收声明。

1. F8 打开后直接输入，分别切换随身／附近，检查原列表和容器图标的命中及匹配组置顶。
2. 输入 `@舌尖`、名称组合、排除、或者及完整 ID，展开同名堆叠核对逐件计数。
3. 在沙盒中选择“仅特殊语法接管”，重进后在 CleanUI 原框输入普通名称，核对原版黄色高亮；再输入 `@来源`、空格 AND、排除或完整 ID，核对紫边和黄色高亮。选中／悬停时检查原背景与紫边。切回“全部接管”后，普通名称也应显示增强效果。
4. 在 CleanUI 原框编辑、清空，再打开增强面板，核对文字和类别；仅特殊模式下 F8 面板的普通名称仍使用增强。启用左键弹出并试一次。
5. 关闭接入，再用 F8 搜索。修改快捷键、保存设置并重进，检查设置读回，切换置顶开关并清空查询确认恢复原排序。Esc 关闭面板。
6. 先拖拽物品并松开，直接点击搜索框输入 `编织` 或其他包内物品名，确认匹配组置顶；不要先点击物品列表。再保持查询，切换类别、排序列、单箱／附近汇总并搬运命中物品，检查计数和置顶。测试 Ctrl／Shift 连选、活动拖拽／框选时延后重排、松开恢复，以及清空查询恢复原排序。
7. 检查原版／Neat 制作建造放大镜跳转，切换英文检查界面、提示、八项模组设置和沙盒选项。

停用后移除本模组即可结束其 UI 功能。查询仅存于当前游戏会话。现有世界物品和存档结构无需迁移。

## 源码与验证

源码位于 `mods/`，独立封面与小 icon 母版、来源及内置 imagegen 提示词位于 `art/`。封面保留原设定人物，icon 为独立生成的透明图。`tools/verify.py` 用原游戏独立 Kahlua 编译产品和测试 Lua，并执行模拟物品、容器、界面及原生 ModOptions 回归，核对中英资源和 PNG。

运行 `python tools/verify.py`。工具中的游戏及 JDK 路径按本机环境配置。结果在 `validation/result.json`。测试不启动游戏或加载存档；实际 UI、玩法和性能验收单独记录。

源码、本地安装、冻结包与发布状态分别记录在项目交付资料中。0.1.0 已于 2026-11-06 上传并核验为私有条目；0.1.2 已获用户当前单人修复确认；当前 Git 与工坊发布状态以 `project.json` 和 `publishing/workshop-item.json` 为准，历史冻结包保留准备时状态。
